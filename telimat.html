1. SPC — Statistik proses nəzarəti

SPC prosesin “normal” fərqlənməsini “həyəcan doğuran” fərqlənmədən ayırmaq üçündür. Məqsəd: hər kiçik sapmada dayamaq yox, sistemli dəyişikliyi erkən görmək.

CL — mərkəz xətt UCL — yuxarı hədd LCL — aşağı hədd ±2σ zona ±1σ zona
SimvolAzərbaycancaNə deməkdir
CLMərkəz xəttProsesin orta səviyyəsi (məs. orta fakt saat və ya orta ölçüm).
UCLYuxarı nəzarət həddiBundan yuxarı nöqtə «təsadüfi səs-küy»dən çox ola bilər — araşdırın.
LCLAşağı nəzarət həddiBundan aşağı eyni məntiq.
σ (siqma)Standart kənarlaşmaNöqtələrin ortadan nə qədər «yayıldığı».
±1σ1 siqma zolağıNormalda nöqtələrin böyük hissəsi buradadır.
±2σ2 siqma zolağıDaha geniş «hələ ola bilər» zonası; tez-tez kənara çıxma xəbərdarlıqdır.
±3σ3 siqma (klasik UCL/LCL)Klassik nəzarət qrafikində hədlər adətən CL ± 3σ götürülür.
2σ olanda nə olur? 3σ olanda?
  • 3σ həddi: Nöqtə həddən kənardırsa, əksər hallarda «xüsusi səbəb» axtarılır (alət, material partiyası, operator, ölçü xətası).
  • 2σ zonası: Hələ hədd deyil, amma bir neçə nöqtə ardıcıl 2σ-dən kənarda qalırsa, proses sürüşür — gözləməyin, yoxlayın.
  • 1σ daxilində sıxılma: Bəzən yaxşı sabitlikdir; bəzən ölçü «yuvarlaqlaşdırılır» və ya məlumat azdır — kontekstə baxın.

3. Plan–fakt və CV

Plan saat — normadan gələn gözlənti. Fakt saat — növbədə yazılan real vaxt. Hesabat və plan ekranlarında vaxt 4 onluğa (məs. 1.2500) qədər yuvarlaqlaşdırılır.

  • Var_saat_faiz = (Fakt − Plan) / Plan
  • Yaşıl ≈ |fərq| ≤ 5% · Narıncı 5–15% · Qırmızı > 15% (fayldakı rəng qaydası)

CV (əmsal dəyişkənliyi) = σ / orta.

CVOxunuş (sadə)
< 10%Sabit proses
10–25%Orta dəyişkənlik — izləyin
> 25%Yüksək dəyişkənlik — kök səbəb axtarın

Dashboard-da CV nümunə fakt saat sırasından hesablanır; real işdə 7_Fakt sütunlarından götürülür.

4. Sərbəst qalıq (köhnə “ATP” sözü)

Faylda ingiliscə ATP yoxdur. Azərbaycanca:

  • Sərbəst — yeni iş əmrinə / tələbnaməyə indi verilə bilən miqdar
  • Rezerv — başqa iş üçün tutulub, verilmir
  • Blok_Zay / Blok_QC — yararsız və ya yoxlama bitməyib
  • Serbest_kifayet — Sərbəst ≥ Min_stok → Kifayət, yoxsa Çatışmır
Planlamacı olmayan üçün bir cümlə: «Bu malı bu gün sexə vermək olarmı?» — cavab yalnız Sərbəst sütunundadır.

5. İş axını: Başlat · Bitir · QC

is-axini.html ekranında hər addım üçün:

  1. Başlat — iş mərkəzi aktiv/məşğul olur, görən rol görünür.
  2. Bitir · devret — addım bağlanır, növbəti avtomatik «növbədə» olur.
  3. QC addımı — Keyfiyyət mütləqdir: QC keçdi · devret və ya QC qaldı (axın dayanır, əvvəlki istehsal addımına qayıda bilər).
Qayda: Növbəti əməliyyat əvvəlki bitmədən açılmır. Keyfiyyət qapısından keçmədən yekun montaja «tullanmaq» olmaz.

Kimdə qalıb? Səhifənin yuxarısındakı sarı/mavi zolaq: rol + əməliyyat + iş mərkəzi + status (gözləyir / icrada / bitdi).

5b. Dayanma (naladka) nədir?

Dayanma burada dəzgahın/xəttin effektiv emal etmədiyi, amma iş yerində vaxt aparan fasilədir: təmizlik, ayarlama, alət/frez/bıçaq dəyişimi, yeni məhsula keçid hazırlığı. Rus istehsalat dilində tez-tez «наладка» adlanır.

  • Effektiv iş saatı — Plan_saat / Fakt_saat (7_Fakt): partiya üzrə emal/yığım vaxtı.
  • Dayanma dəqiqəsi — ayrıca göstərici (dashboard nümunəsində); norma saatına qarışdırılmır.
  • Yeni iş əmri tutumu MRP-də norma × ədəd + cari dolu ilə hesablanır; dayanma isə «xətt niyə boş görünmür / niyə gecikir» izahı üçündür.

HTML bitirmə düyməsi Excel-ə avtomatik yazmır. Növbə bitəndə blank C → 7_Fakt mütləqdir; əks halda dashboard/Excel köhnə fakt üzrə qalır.

7. Gündəlik Excel necə doldurulur

Əsas prinsip: əvvəl blank / sex-anbar qeydi → sonra master cədvələ köçürmə. Sarı xanalar əl ilə yazılır; yaşıl xanalar formuladır, toxunulmur.

Günün qısa sırası

  2. Material verilişi: 9_Blanklar forma B (Tələbnamə) → imza → 4_Hareket (CIXIS_IST, miqdar mənfi)
  3. Növbə boyu: forma C (İstehsal) → axşam 7_Fakt-a eyni sütun adları ilə köçür

  5. Zay/QC: forma D → CIXIS_ZAY + Blok_Zay

8. HTML Excel-dən necə qidalanır (indi və sonra)

İndi (praktik, sadə)

Brauzerdəki mrp-planlama.html, is-axini.html, dashboard.html daxilində nümunə məlumat var (Excel kodları ilə eyni dil: HM.NSO…, DM-20…). Gündəlik iş belədir:

  1. Excel-i doldurun / yeniləyin (yuxarıdakı gündəlik sıra).
  2. Planlama və ya analiz üçün lazım olan sətirləri Excel-dən baxıb HTML seçimlərində eyni Mal_Kodu / Mehsul_Kodu / iş əmri ilə işləyin.
  3. MRP ekranından «Yeni iş əmri (.xlsx)» düyməsi ilə çıxan faylı arxivə və ya 4_Hareket / sex blankına istinad kimi saxlayın.
  4. İş axınında Başlat/Bitir/QC — operativ lövhədir; növbənin rəsmi rəqəmləri yenə 7_Fakt-a düşməlidir.
Excel → HTML əl ilə «çəkmə» (bu gün üçün kifayət)
  • 5_Saldo → Planlamada «Sərbəst kifayətdirmi?» ilə eyni məntiqi yoxlayın.
  • 3_Rota + 2_BOM → MRP-də məhsul seçimi və tələbat ağacı.
  • 7_Fakt → Dashboard CV və plan–fakt rəngləri üçün mənbə.
  • İş əmri nömrəsi (Is_emri) hər yerdə eyni yazılsın ki, izləmə qırılmasın.

Sonra (GitHub / avtomatik)

Excel-i repoya qoyduqda növbəti inkişaf addımları belə planlaşdırılır:

  1. Excel-i .xlsx olaraq eyni qovluqda saxlamaq (və ya export .csv vərəq-vərəq).
  2. HTML-ə «Fayl seç / yüklə» ilə Excel oxuyucu (brauzerdə) vasitəsilə 1_Mallar, 5_Saldo, 7_Fakt oxutmaq.
  3. MRP və dashboard-un nümunə massivlərini bu yüklənmiş cədvəllərlə əvəz etmək.

Bu avtomatik yükləmə hələ məcburi deyil: əvvəl gündəlik Excel intizamı otursun, sonra bir düymə ilə «Excel-dən oxu» əlavə olunur.

Rəqəmlər

Plan və hesabatda vaxt/miqdar HTML-də ən çox 4 onluq (1/10000) göstərilir. Excel-də də eyni prinsip tövsiyə olunur.
